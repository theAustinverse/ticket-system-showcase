# 1. 專案要解決的問題

## 搶票瞬間：固定座位、大量同時請求

活動座位數固定，開賣當下大量使用者在同一時間送出購買。系統要同時做到兩件事：

1. **一張都不能多賣**：即使上千個請求同時到達，賣出的數量不能超過座位數。
2. **流量不能壓垮下單流程**：同時進來的人要排隊、依序放行，而不是讓伺服器一起處理所有請求。

一般「先查剩幾張、再扣一張」的做法，在大量同時請求下會讓多個請求同時看到「還有票」而一起成交，造成超賣。這是本系統最核心的問題。

## 活動當天：入場要快、不能被冒用

- 每個座位需要自己的入場憑證，同行者也要能各自入場。
- 票券轉讓後，原持有人手上的截圖必須失效。
- 同一張票不能用兩次，即使兩位工作人員同時掃到同一張 QR。

## 票券之後的變動

- **轉讓**：要等收票人確認才移動，過程中不能出現一張票兩個主人。
- **修改與退票**：購票人能自行修改同行者資料；退票後座位要正確回到可售狀態。
- **後台修正**：管理員要能修正座位資料、調整所屬團隊、取消訂單，並留下修改紀錄。

## 營運面的需求

- 公開的聯絡窗口、防詐騙提醒、使用教學。
- 小額贊助的對帳（系統看不到銀行轉帳備註，需要另外的對帳方式）。
- 常見操作問題的自助回答，減少人工客服負擔。
