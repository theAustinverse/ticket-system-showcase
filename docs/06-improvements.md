# 6. 系統還可以改良的地方（自我檢視）

這一頁列出我認為系統還可以改良的地方，作為自我檢視與反省。每一項都對照程式確認過目前的實際行為。

## 1. 轉讓截止時，自動退回尚未被接受的轉讓（目前沒有）

**原本的設計想法**
轉讓截止前，如果對方還沒接受，就自動退回原申請人。這是我當初的設計想法，實際運作的情形我沒有親眼看過。

**目前的行為**（依程式核對）
- 待處理的轉讓沒有期限，系統不會自動取消或標記逾時。
- 收票人接受前，票券的持有人不會改變。
- 每一波可以設定「轉讓截止時間」。截止後不能發起新的轉讓，也不能再接受截止前已發出的邀請；邀請仍可由收票人拒絕或由原持有人取消，否則會一直停在「待處理」。
- 波次的銷售結束時間不影響轉讓。

因此，截止後票券實際上會留在原持有人手上，只是那筆轉讓邀請不會自動結束。

**下次可以優化和調整的地方**
轉讓截止時，自動把尚未接受的邀請結束，並通知雙方。

## 2. 條碼掃描報到系統做得更全面

**目前的做法**（依程式核對）
- 每個座位都有一張專屬的入場 QR，同一張只能報到一次。
- 現場工作人員使用專屬帳號登入，用手機掃描 QR 報到。
- 有各團隊的報到名單，也可以查詢與統計報到人數。

**下次可以優化和調整的地方**
明年把條碼掃描系統做得更全面，讓簽到報到更有效率。
